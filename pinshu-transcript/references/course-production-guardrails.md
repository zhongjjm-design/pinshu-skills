# Course Production Guardrails

## Course-Editing Production Guardrails

1. **Convert spoken numbers to written form**: Convert spoken dates (`nine fourteen` -> `September 14`), numbers within product names (`iPhone seventeen` -> `iPhone 17`), spoken percentages (`X percent` -> `X%`), and spelled-out quantities in data contexts (`one hundred fifty-eight customers` -> `158 customers`) to written form. Preserve rhetorical quantities such as “a hundred million,” “the hundredth person,” or “three or five times.” Write every replacement back to the terminology proofreading table.
2. **Corrections must reach every reader-facing text**: Each time the glossary or proofreading table records a mapping, apply it immediately to the main text and derivative pages (including quote lists and indexes), then search each display surface for the old spelling. Keep the STT error only in immutable raw material, the glossary's mapping, or internal source-trace notes. An edited quotation with corrected words, punctuation, or fillers must be labeled an **edited quotation**, never a verbatim quotation. Recheck all mappings before delivery; recording without correcting is not completion.
3. **Paragraph and frontmatter hygiene**: A single Markdown line break does not create a paragraph; after splitting or deleting paragraphs, ensure blank lines remain between them. Frontmatter fields must not contain blank lines. The frontmatter closing line must not be followed immediately by a `---` separator. Escape vertical bars in wiki links inside table cells as `\|`.
4. **Punctuation preference**: The user rejects dense em dashes. Rewrite them as colons when introducing a list or commas for parenthetical additions. Then scan the full text for duplicated full-width commas (`U+FF0C U+FF0C`), a full-width colon followed by a full-width comma (`U+FF1A U+FF0C`), and paragraphs beginning with punctuation.
5. **Library conventions override defaults**: Before entering a course library, resolve manifest/path-map keys and inspect the existing catalog and drafts. Follow its numbering, naming, and layout instead of translating public English labels into paths. Do not create a synonymous cross-course directory when the function already has an established target. Known convention for the Hundun course library: use the official timetable title as the filename; express the content type through the directory and frontmatter; omit the H1 and source paragraph from the body.
6. **Select and use event photos**: After ingesting on-site slide photos, review every image in a thumbnail sheet and record each slide's topic. Select high-information key slides, such as frameworks, models, comparison tables, and data slides, and embed them in the matching sections of the faithfully edited draft. Do not ingest images without using them. A course handout may link to the slide deck instead.
9. **Experience write-backs need provenance and a validation scope**: When promoting a course-specific exception to a general rule, record the triggering course, the corrected failure, and the sample range already validated. File modification times do not prove contributor identity. Do not credit an agent without commit history or an operation log.
