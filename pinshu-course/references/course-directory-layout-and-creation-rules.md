# Course Directory Layout and Creation Rules

The actual course map, directories, peer files, and source library define runtime paths; public English labels do not. Read the existing course map (whatever its current filename and language) first. Reuse established numbers and synonymous sections. Do not create translated parallel trees or empty optional folders.

For a new course with no established structure, agree on one explicit project-specific path map before writing; the example in `../SKILL.md` is a model, not a mandated filename. Bind identity, authoritative source, and the single formal write root. A manifest may be used when an actual upstream course-capture workflow supplies one, but this Skill does not require a manifest or assume that `course_pipeline.py paths` exists on every installation. If an existing course-capture tool provides resolved paths, verify them against the course map and approved root; otherwise inspect the actual directory and confirm targets before writing.

The four required results are: immutable raw transcript, faithful edit, structured lecture, and an idempotent shared-map entry. Review/training content appears only for an enabled learning purpose; learning records only after genuine study or answers. Dissemination folders appear only after explicit enabling and actual qualified content. Visual-assets and production-control areas appear only when they have a user. Keep raw intake separate from formal expert-owned knowledge.

Do not substitute a generic learner's name or an agent's name in generated directory or template structure. Render human-facing material in the user's requested or existing course language. Stable machine keys and index types remain English. Resolve every relative source or metadata-index pointer from the file that owns it before promotion.
