# 专业课程学习资产流水线

## 目标

用于中医、术数、学术或其他以“学会、复习、训练、跨课串联”为主要目的的系列课程。Aidan不需要记Skill名称；主控按自然语言路由。

## 组合

```text
pinshu-transcript：原始转写 → 忠实精编稿
pinshu-distill：忠实精编稿 → 结构化讲义；模块资料 → 正式横向专题
pinshu-study：讲义 → 主动回忆卡；带学、训练、错因和个人记录
pinshu-course：课程身份、进度、断点、待归并知识线索和正式提升
```

## 前台与后台

### Aidan前台

- 结构化讲义；
- 一次呈现一张的中文主动回忆卡；
- 中文带学或训练对话；
- 模块完成后的正式横向专题；
- 课程地图中的简明学习路径和待串联摘要。

### Agent后台

- 原始来源、锚点和身份；
- 术语、QA和返工；
- 生产状态与规则版本；
- 待归并知识线索；
- 卡片、题目和学习记录的机器字段。

后台可以审计，但不占据主要学习界面。

## 每课

1. 原始资料可用；
2. 忠实精编稿通过来源和语义QA；
3. 结构化讲义突出重点、组织顺、独立可学；
4. 主动回忆卡正文为中文，一次一个主要目标；
5. 课程地图更新；
6. 只登记有明确跨课价值的待归并知识线索。

不默认每课生成完整模拟题或正式横向专题。

## 模块

- 合并逐课主动回忆卡，跨课去重并生成模块综合卡；
- 优先映射用户已有题库；
- 生成模块带学与混合训练；
- 把待归并线索合并、去重、保留差异；
- 生成Aidan可读的正式横向专题。

## 待归并知识线索

它是材料收集篮，不是正式学习文档。每项至少说明：知识对象、本课新增内容、跨课理由、后续触发、证据状态、本课来源；只有“跨课已验证”必须再给第二来源。

证据状态只使用：本课候选、后课伏笔、跨课已验证、安全治理候选。预计复现不等于已经跨课；没有第二来源时不能标“跨课已验证”。

只有以下情况登记：

- 明确后课伏笔；
- 已连接多个模块；
- 强混淆或强分歧；
- 安全治理价值；
- 跨期、跨老师变化。

普通单课细节不登记。课程地图只显示中文摘要。

## 学习触发

用户仅提交课程、讨论整理或打开讲义，不自动训练。用户说“开始学、带我学、考考我、复习、练错题”时调用`pinshu-study`。

状态：

- 未学 → 带学；
- 刚学完 → 基础回忆；
- 已复习 → 推导、比较和混合训练；
- 有错题 → 针对复测。

## Markdown与网页

Markdown是讲义、卡片、题库、作答和状态的事实源。网页后置，只读取这些资产；网页数据库不得静默覆盖Markdown原文。

## 并发与正式提升

正式课程库单写者。子Agent只写独占临时目录；主Agent完成程序统计、来源路径核验、内容QA和前台阅读检查后串行提升。生成者自评只作返工线索；候选、生成、自检、独立QA、返工、复验和验收状态分开。模块结束时，跨课卡片聚合与去重由`pinshu-course`负责，`pinshu-study`只负责卡片生产和学习使用。

## 放量门槛

整门课程批量生产前至少验证：

1. 一个综合单课样本；
2. 一个病案／例盘样本；
3. 一个强视觉／实操样本；
4. 忠实稿、讲义、主动回忆卡和课程地图的独立QA。

真实“带学→回忆→追问→回源→记录”用于验收学习运行体验；它不是生成每课主动回忆卡、更新课程地图或进入课程批处理的前置批准。没有真实作答时只能保持“未开始”，不能伪造学习进度。模块正式横向归并和混合训练在模块收官时完成。历史试点课只作为验证证据，不作为当前生产闸门。
