# 课程整理的价值优先与学习／传播分层

## 适用场景

连续整理课程、演讲或现场分享时，用这份规则防止学习资产、传播资产和平台成品互相污染。

## 价值顺序

课程整理首先提取用户真正要带走的知识：

1. 课程最重要的判断；
2. 完整方法、推导与案例；
3. 可执行动作、工具与关键数字；
4. 讲师独有经验及其适用边界；
5. 必要的事实、安全和合规说明。

每课核心结果仍是原始转写、忠实精编稿、结构化讲义和课程地图唯一条目。传播价值重要，但不再通过每课固定尾部字段来证明。

## 学习资产阅读顺序

```text
本课核心（最多3条）
→ 忠实精编稿
→ 系统化方法与完整案例
→ 执行清单、工具与关键数字
→ 编辑核验与边界说明
```

文首不放冗长编辑说明。风险会改变执行安全或结论真伪时，就地短提示，并在适当位置集中说明。

## 传播资产独立分流

用户明确需要传播用途时，调用 `pinshu-content-assets`：

- 单篇直播／访谈／演讲形成篇级传播母资产；
- 系列课程逐课只捕捉有增量候选；
- 模块结束形成阶段精选；
- 完课后形成课程级传播母资产；
- 平台成品由配置的下游内容工作流负责。

学习稿不再强制包含金句、传播观点、用户连接点或朋友圈候选。传播层有独立 Schema、状态机、风险规则和验证器。

## 主次失衡的失败信号

出现任一情况应返工：

- 文末核验说明比课程价值区更醒目；
- 有完整逐字稿，却没有可扫读的本课核心；
- 为了传播字段删减课程案例或推导；
- 为填数量制造讲师金句、用户经历或朋友圈文案；
- 把未完课阶段资产写成正式课程级母资产；
- 把平台草稿混入忠实稿或讲义；
- 目标路径未配置，却声称平台稿已交付。

## 内容完成与落盘完成分开

状态只能按真实证据推进：

1. `内容已整理，尚未写入`；
2. `文件已写入，尚未验收`；
3. `已落盘并验收`。

传播层还须区分母资产完成、handoff 准备、草稿生成、人工定稿和目标交付。生成 handoff 包不等于已经交付；外部写入后必须读回目标。

## 验收清单

- [ ] 四项课程核心结果完整；
- [ ] 忠实精编保留话脉、过程、数字与案例；
- [ ] 系统讲义可脱离原视频独立学习；
- [ ] 学习资产验证器不要求传播字段；
- [ ] 传播资产由独立 Skill 和验证器处理；
- [ ] 原话、编辑提炼、用户延伸与外部补充分层；
- [ ] 高风险内容没有越过核验和人工审核闸门；
- [ ] “已落盘”或“已交付”都有目标证据。
