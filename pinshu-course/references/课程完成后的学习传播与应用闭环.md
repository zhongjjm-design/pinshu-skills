# 课程完成后的学习、讲述、应用、传播与资产化闭环

## 核心判断

逐字稿和讲义只是可用底座，不等于用户已经掌握、应用或能对外表达。课程完成后按用户真正需要的结果分流，不默认把所有派生产物一次生成。

## 六种结果

### 1. 理解

使用 `pinshu-distill` 生成结构化讲义、概念关系、方法条目和正式横向专题。验收标准是没看过原课的人也能说清问题、原理、步骤、条件、案例和边界。

### 2. 掌握

使用 `pinshu-study` 做主动回忆、追问、错因、回源和复测。读过、划线和收藏不能标记为掌握。

### 3. 讲述

使用 `pinshu-study` 的费曼讲述路径：用户先不看稿讲，Agent 扮演听众追问，识别概念、推导、案例、证据、边界和表达漏洞，回源后再次讲述。

### 4. 应用

选择具体业务问题，写清采用哪条课程判断、成立前提、动作、指标、停止条件和复盘时间。执行后区分方法无效、条件不满足和执行不到位。

### 5. 传播

使用 `pinshu-content-assets`，而不是在每课正文末尾固定附加传播字段：

- 单篇直播、访谈或演讲形成篇级编号化内容资产，默认交付可直接使用的表达、选题、内容任务卡和导航；
- 系列课程逐课在后台捕捉候选，按已完成范围交付阶段内容资产，完课后形成课程级内容资产；候选与母资产不是默认交付终点；
- 每项区分表达身份、来源锚点、核验状态和风险等级；
- 平台稿通过可配置 handoff 交给下游内容生产工作流；
- 下游目标未配置时标记 `destination_unresolved`，不猜路径或声称下游交付；仍应在已批准的项目位置完成本地内容资产。

### 6. 资产化

把多次真实应用中稳定有效的方法沉淀为案例、SOP、Skill 或产品。课程讲过的方法只是候选；至少经过一个真实场景验证，并写清适用条件、失败模式、验收标准和人工边界后，才进入正式能力库。

## 推荐闭环

```text
原始证据
→ 忠实精编稿
→ 结构化讲义
→ 横向知识图
├→ 主动回忆与讲述训练
├→ 真实项目迁移与复盘
└→ 后台候选归并 → 编号化可用内容资产 → 按需下游内容生产
→ 经验证的方法升级为案例、SOP、Skill或产品
```

这不是每课必须跑完的固定流水线。用户只想查原话时停在忠实稿；只想理解时停在讲义；明确要学习、应用或传播时才继续。

## 证据与目录纪律

1. 先读课程地图并检查已有目录；存在同义栏目就沿用。
2. 忠实稿、讲义、训练、学习记录、传播母资产、平台成品和业务应用记录分开保存。
3. 用户第一次讲述必须保留，不能只留 AI 润色稿。
4. 传播资产不回写污染忠实稿与讲义；课程地图只放传播入口和状态。
5. 真实项目结果回写应用记录；跨场景稳定成立后才升级为通用能力。

## 最小验收

- 讲述训练保留第一次讲述、追问、漏洞、回源和第二次讲述；
- 应用训练保留假设、动作、指标、停止条件和结果；
- 传播资产区分讲师原话、编辑提炼、用户延伸和外部补充；
- 外部核验与表达身份是两条独立轴；
- R2 未核验、R3 未完成人工审核与证据记录时，按内容资产 Skill 当前合同隔离，不能进入可直接使用资产、选题或任务卡；
- 默认完整传播任务须阅读实际成品并通过项目级 `full-delivery` 验证，单独的注册表 PASS 不等于完成；
- 资产化条目能回答何时用、为什么、怎么做、何时失效和如何验收。
