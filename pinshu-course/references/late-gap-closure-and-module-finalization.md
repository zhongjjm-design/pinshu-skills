# 迟到缺课补齐与模块收官

适用于：课程曾因跳号输入形成模块缺口，后续用户补发最后一节缺课；补齐后该模块第一次达到全课齐备。

## 核心判断

“补齐一课”同时触发两类状态变化：

1. **逐课状态**：本课从待输入变为双稿完成、预览验收通过；
2. **模块状态**：模块从 `N-1/N` 变为 `N/N`，需要执行模块级收官，而不是只更新一行目录。

不要把这类任务当作普通单课处理。

## 一、先判断资料是否构成完整一课

至少核对：

- 开头是否有正式开课或稳定主题锚点；
- 结尾是否有下课、问答结束、下一课提示等边界；
- 是否出现系统级 `[truncated]`、续传提示或明显大段缺失；
- 局部引文、口述或STT不完整，是否只影响一个引用而不影响整课边界。

### 局部残缺不等于整课截断

若整课首尾完整，只有某条引文、姓名或句子口述/识别不完整：

- 可以正常生成双稿；
- 在编辑说明、风险边界或待核记录中明确局部缺口；
- 不凭常识补原句；
- 不把整课状态写成“待补全文”。

只有系统截断、后半课缺失或用户明确说“还没发完”时，才回到收集态。

## 二、处理官方标题与课堂自报名差异

权威顺序：

```text
官方课程目录/已确认课程地图
> 课堂开场自报名
> STT推测标题
```

执行规则：

1. 文件名、H1、`original_title`、地图目录行、预览文件名统一采用官方标题；
2. 忠实稿编辑说明和讲义导读保留“课堂自报名为……”；
3. 不把二者强行改成完全相同，也不把自报名丢失；
4. 若两者可能是实质不同课程而非措辞差异，暂停并询问。

## 三、双稿要保留课堂中动态形成的方法体系

课堂可能先说“六种方法”，互动后又新增第七种，或把某项归并到另一项。

应同时保留：

- 开场时的方法数量；
- 课堂互动带来的新增项；
- 讲师最后的归并判断；
- 系统讲义按课堂终态建立总览。

不要为了目录整齐，抹掉方法体系在课堂中形成和修正的过程。

## 四、地图必须原子更新的状态面

最后缺课补齐后，一次性检查并更新：

1. frontmatter `current_progress`；
2. frontmatter `next_lesson`；
3. 已收到转写集合；
4. 已生成双稿集合；
5. 已验收集合；
6. 已完成模块；
7. 当前模块；
8. 下一课；
9. 模块完成比例；
10. 全课程已整理总数；
11. 本课目录行与双稿链接；
12. 本课知识导航；
13. 后续已整理课程中提及的“本课缺失/非连续归档”说明；
14. 后续模块收官段里的“缺课、N-1/N、不做横向归并”等陈旧表述；
15. 文末下一课说明。

### 必做残留扫描

至少搜索：

- `第XX课待输入`
- `第XX课尚未收到`
- `第XX课缺口`
- `N-1/N`
- `（缺课）`
- `验收推进中`
- `下一课为第XX课`
- `当前模块：旧模块`

残留为0后，才可宣布模块闭合。

## 五、模块闭合自动触发五件套

模块首次达到 `N/N` 时，生成或更新：

1. `03_横向方法论库/[模块]·核心方法论.md`
2. `04_案例库/[模块]·案例索引.md`
3. `05_工具与清单/[模块]·执行清单.md`
4. `06_事实核查/[模块]·事实与风险清单.md`
5. `07_练习与作业/[模块]·模块作业.md`

五件套必须是模块级归并，不是把单课讲义拼接在一起。

### 核心方法论

回答模块共同解决的总问题，给出跨课因果链、统一SOP和能力标准。

### 案例索引

按“案例解决什么问题”分类，标明来源课次、用途和待核状态。

### 执行清单

把跨课方法转成可填写、可验收的生产工具。

### 事实与风险清单

分稳定原理、讲师经验、时效规则与高风险主张，汇总转写缺口和历史验收限制。

### 模块作业

设计一项贯穿全模块的真实交付，而不是逐课作业简单相加；应包含第一版、盲测/发布、复盘和控制变量第二版。

## 六、预览同步采用两阶段终态

### 第一阶段：内容同步

同步：

- 本课忠实稿；
- 本课讲义；
- 当前地图；
- 模块五件套。

保留双稿相对目录，避免同名覆盖。

### 第二阶段：终态地图同步

内容和模块文件验收通过后，地图通常还要把“推进中”改为“通过”，并把当前模块切到下一模块。

因此必须：

1. 完成状态终改；
2. 再同步一次地图；
3. 对逐课预览地图和模块预览地图分别做文本比较；
4. 再执行一次旧状态残留扫描。

不要把第一阶段的临时地图当成最终地图。

## 七、非SHA验收模板

用户明确不执行SHA时，可使用：

- 文件存在性；
- 标题/frontmatter读取；
- 唯一锚点与占位符扫描；
- 忠实稿第一人称红线扫描；
- 源端与预览端逐文件文本比较；
- 地图旧状态残留扫描；
- 模块五件套完整性与来源课次覆盖。

结果记录：

```text
lesson_faithful_equal=true
lesson_lecture_equal=true
lesson_map_equal=true
module_five_files_equal=true
module_map_equal=true
stale_state_count=0
sha=not_run
```

## 八、常见错误

### 错误1：只补双稿，不解除非连续状态

后果：地图和后续讲义仍声称本课缺失。

### 错误2：模块比例改成N/N，但不做横向归并

后果：违反“模块结束集中归并”的知识库节奏。

### 错误3：过早把验收写成通过

后果：预览尚未真实存在，地图已经宣告完成。

### 错误4：只同步一次地图

后果：预览保留“验收推进中”“当前模块为旧模块”等临时状态。

### 错误5：把局部引文不完整当成整课截断

后果：无谓阻塞完整课程入库。

### 错误6：用常识补全引文

后果：忠实稿混入未经提供的原话。

### 错误7：模块五件套写成单课复制品

后果：没有形成跨课工作流、风险结构和可执行资产。

## 九、完成条件

只有同时满足以下条件，才能宣布模块收官：

- 最后一节缺课双稿完成；
- 本课知识导航完成；
- 模块比例和总课数正确；
- 后续课程的缺课说明已清理；
- 五件套生成或更新；
- 地图已切换到下一模块和下一课；
- 本课、模块五件套和终态地图预览一致；
- 旧状态残留为0；
- 截断、STT、事实、版权和平台规则风险已显式记录。
