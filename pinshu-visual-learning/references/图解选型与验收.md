# 图解选型与验收

由主文件在完整读完当前讲义后调用，本文件只帮助已选定的图解任务，不重新决定任务范围。

## 先讲清一屏

一屏让学习者看见：这一课的问题、核心关系、从哪里读起。章节不是模板数字；标题用内容问题引导。主结论、图形标签、正文、来源注释形成明确层级。重要信息不能用淡灰小字承担。

## 按关系选图

| 来源真实存在的关系 | 图形承担的任务 | 易错点 |
|---|---|---|
| 分类或层级 | 显示共同父项和不同分支 | 不把并列分支连成因果 |
| 有顺序的操作 | 表示动作、输入、反馈与停止条件 | 不省略操作前提 |
| 判断分叉 | 展示条件成立时的不同走向 | 不把不确定项当肯定条件 |
| 相互作用 | 节点与标注连线说明作用 | 箭头必须有含义，不是装饰 |
| 比较 | 同一尺度显示关键差异 | 不把文本硬挤进大表 |
| 案例推导 | 从问题到动作、结果与边界 | 真实结果和讲师归因分开 |
| 概念坐标 | 标明轴、相对变化、区域 | 概念示意无刻度，不伪造定量 |
| 事件或演化 | 时间线保留事件和转折 | 时间相邻不等于因果 |

## 可读性与吸引力

- 以中文阅读的正常大小验收，不靠屏幕缩放。手机内容列宽取目标页面实测值，不固定为351px；逐图记录实际显示宽、最小显示字号和横向溢出，100%缩放时最小显示字号不低于11px。宽图能满足就保留，达不到再拆图或另做窄屏图，不把所有课程强改成同款卡片，也不用整页长截图。
- 每张图只保留理解关系所需标签，详细解释放在图旁正文。长内容不是“字号变小”的理由。
- 色彩服务角色：主线、比较、条件、风险明确区分；相同角色全课一致。用文字和形状补足色盲可读性。
- 深色文字与足够留白支撑阅读；暖红、绿色等可以作为有含义的强调，但不设所有课程固定配色。
- 允许信息密度变化：大关系图、短解释、案例推演、比较与复习交替；不把所有章节做成同款框。
- 已批准的课程视觉系统沿用；试制样稿不能变成所有课程的固定模板。

## 来源与风险

图中每项知识能在讲义定位，出现解释歧义时继续回源。不要求每个标签暴露内部ID。用读者能理解的来源说明保留可复查依据。

个案、讲师观点、编辑示意、外部核验、待确认分别表达。商业数字与健康功效等高风险主张近邻标明，不能借图解把它变成确定答案。

## 实际验收顺序

1. 图形语义：逐一对照节点、连线、步骤、区域、图例、坐标和数字。
2. 学习任务：初学者能回答本课讲什么、知识如何联系、怎么判断/操作、哪些情况不能直接下结论。
3. Markdown结构：图片及来源链接从当前最终位置解析，正文可搜索，正式稿 `kind/status` 正确，同名SVG源通过XML解析且可编辑。
4. HTML结构：无外部资源依赖，同源内容一致，图片有 `max-width:100%`，来源区使用可点击 `<a href>`。
5. 桌面：文首、最密模块、案例和文末，检查断行、重叠与图中文字。
6. 手机：检查实际窄屏，不用“响应式CSS存在”代替页面；分模块图需另核窄屏显示。
7. Obsidian：由Agent或用户在实际阅读视图完成整篇检查，核图片、属性、来源和正文，并记录真实阅读证据。未进入正式库的样稿可以做临时阅读验证，但必须明确不同于正式库相对路径验收；静态检查与浏览器预览不能冒充实读。
8. 工作台：若是本次目标，再核对图片路由。未实测就记未验证，不因为Markdown组件存在宣称兼容。

脚本、文件和截图各有覆盖边界：脚本不证明语义，单张截图不证明全页，浏览器不证明Obsidian。对用户先交成品，再用简短话说明仍未验证的位置。
