# 品叔图解学习

## 来源与维护

- 原创身份：品叔原创（original）
- 原创归属与维护者：Aidan（品叔）
- 上游：`pinshu-distill` 提供已验收讲义，`pinshu-transcript` 提供回源正文；课程编排由 `pinshu-course-capture` 与 `pinshu-course` 负责。
- 原创能力：依据学习任务选择图形、区分学习表达与原课证据、Markdown优先的双载体交付及图形语义与实际阅读验收。
- 分发状态：14 项统一公开候选之一；课程图解仍需清单显式启用、样稿/批量授权和真实阅读证据，不能自动批量生产。

## 用户得到什么

把讲义中已经确认的知识关系做成可扫视、比较、定位、回忆的图解学习版。主交付是 **Markdown文字＋分模块PNG图片**，保留可编辑SVG图源；同一内容生成自包含HTML辅助版。Markdown中的正文和来源仍可搜索，不把整页网页截图当成唯一阅读稿。

图解版是学习层，不替代原始转写、忠实稿、结构化讲义、复习训练或真实学习记录。知识地图只是其中一种图，不是整份交付物的名字。

## 第一判断与输入

1. 总入口传来课程图解任务：核对课程身份、课次、已验收讲义、允许写入路径、来源不确定项和样稿批准状态，继续这一课。
2. 用户单独要求已完成讲义的图解：直接制作图解层，不重新跑采集和双稿。
3. 用户只要求校对逐字稿、带学、考问或传播素材：交回对应能力，不扩张成图解生产。

正常生产必须先有讲义语义验收。若只有用户认可的待验样例或未验讲义，可以在明确的试制授权下制作候选，但标记“视觉样稿，来源与图解均待验收”，不能提交正式通过报告。原课资料仍只读。

讲义有疑问时查忠实稿；仍有疑问再查原始转写或真实画面。不确定关系不连成确定箭头。缺失课件不阻止绘制其他有可靠来源的关系，但对应缺口就地标明。

## 正常流程

### 1. 先找学习主线

完整读讲义，确定读者要理解、比较、判断或操作什么。内部规划：主问题、核心关系、必要案例、条件与反例、目前不能学的内容。不先选颜色或套图形。

### 2. 选图形并组织内容

读取 `references/图解选型与验收.md`。按本课真实关系组合模块，不规定每课图数：

- 层级或分类：树、分组与总览；
- 判断或操作：带条件的流程与分叉；
- 对比：围绕关键差异的对照；
- 因果或相互作用：标明关系含义的连线；
- 推导：条件→依据→判断→边界的案例；
- 时间演化：时间线；
- 误解：错误理解、纠正依据与正确边界；
- 纯故事或访谈：事件线、人物观点与比较，不强造模型。

图形必须承担解释任务，不把长段文字塞进方框冒充图解。编辑学习路径、分类和示意图标明是编辑整理；顺序和箭头不能凭排版暗示来源没有的因果或必经流程。

### 3. 制作Markdown主稿和图源

一张图说明一个主要关系，复杂图拆为几张，正文在图旁解释节点、关系、条件和案例。关键学习内容同时保留可搜索文字，图不能成为唯一知识来源。

使用标准Markdown相对图片链接 `![说明](相对路径.png)`，便于Obsidian与其他阅读器使用；图与正文在同一交付包里。SVG为编辑源，PNG为兼容阅读图。仅简单且目标阅读器已经实测支持时才用Mermaid；不依赖未安装插件或全库主题修改。

图解主稿 frontmatter 至少写 `kind: 图解学习` 与 `status`。试制时只能写 `候选` 或 `待验收`；正式提升前改为 `正式`，并重新绑定报告。校验器只判断字段值，不因正文正常出现“候选”二字拒绝整篇。来源链接必须从最终文件位置解析；HTML 来源区使用可点击的 `<a href>`，不能只放代码文字。

正文、图形与资产名称服从课程既有命名规范和当前写入批准。所有图片无frontmatter。文章署名和元信息不占据图解第一视觉层。

### 4. 同源HTML辅助版

用同一知识结构、同一图源和来源说明制作HTML，不另写一套事实。CSS、SVG与需要的图片内嵌，不依赖外部字体、CDN或在线脚本；本地打开可读。桌面和窄屏分开排版，不能靠缩小整页来适配手机。

视觉方向未批准时先做代表性样稿。现阶段不固化八字样例的颜色、模块数量或布局；知识分类、重点与风险用文字和形状共同表达，不只靠颜色。

### 5. 看内容和看实际页面

先把图中节点、箭头、数字、坐标、区间、条件与讲义逐一核对，再打开真实Markdown和HTML看阅读效果。尤其核对：坐标区域有没有涂反、箭头方向有没有反、并列关系有没有误画成先后、讲师案例有没有升级为外部事实。

运行 `scripts/validate_visual_learning.py --md <图文稿.md> --html <辅助页.html> --mobile-content-width <实测内容列宽>` 检查确定性问题；候选稿已按最终位置编写回链时，加 `--link-base <正式图解目录>`；正式提升时再加 `--formal`。脚本检查图片与来源回链、HTML依赖、同名SVG的XML合法性，并按实测内容列宽折算图中文字。内容列宽来自目标页面实测，不固定为351px。它仍不能证明图形语义正确、整篇内容完整或用户愿意继续看。

在桌面、手机宽度、Obsidian阅读界面检查文字大小、对比、图片可读、段落、断链、重叠和溢出。手机逐图登记实测视口宽、内容列宽、显示宽、最小显示字号和横向溢出；图形可以是宽图、竖图或拆图，不要求全部套成同款卡片，只要求100%缩放时无需横滑且最小显示字号不低于11px。若不能实际验Obsidian，报告“未验”，不能用浏览器预览替代；Obsidian通过必须由Agent或用户完成整篇真实阅读并留下证据。工作台图片路由也需实际测试，普通React Markdown组件存在不等于图片已接通。

### 6. 交接并停止

交回Markdown、HTML、SVG/PNG资产、来源与未决项，以及实际检查记录。启用的课程由总控登记路径与课程地图，唯一提交者正式提升。按管线合同提交图解报告；`checks` 固定使用 `semantic`、`desktop_render`、`mobile_render`、`obsidian_render` 四个布尔键。手机另交 `mobile_evidence`，Obsidian另交 `obsidian_evidence`；机械、语义、桌面、手机、Obsidian检查分开记录，未检查就不能填true。机器通过与用户样稿批准是两件事，不能相互代替。

来源不足到无法形成可靠关系时，明确不生成原因，交总控记录；不能用“本课不适合画图”规避已有关系。样稿未获用户批准，不批量、不擅自入库、不发布。

## 原课视觉与学习表达的区别

原课PPT、板书、例盘、截图和手势是证据，只能使用实际取得的画面。重新设计的学习图可以表达可靠文字中已确认的关系，必须标为学习示意，不冒充课件复原。讲师经验、医疗内容、商业数据和待核项的身份与边界放在相关内容旁，不能只靠文末声明。

## 完成标准

- 知识关系与来源一致，核心内容在图或正文中有去处；
- Markdown可搜索、图片相对链接可解析，HTML与其内容一致且自包含；
- 图形承担解释任务，正常阅读大小下可读，不靠放大补救；
- 真实目标界面检查已执行或明确未完成；
- 用户收到实际文件和准确状态，不把“文件存在”“脚本通过”说成“图解学习能力已验收”。
