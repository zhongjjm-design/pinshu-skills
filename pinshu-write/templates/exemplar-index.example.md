# Exemplar index (example)

The writers' main input (`references/write.md`, "The writer's brief", item 4). Use the article types of your good-article standard. Point the configuration's `exemplar_index` at your copy of this file. One row per article. Article texts stay where they already live in your library; this index only points at them, so there is never a second copy to drift.

Only rows marked `approved` are used: the author read the article and wants writers to learn from it. `candidate` rows wait for the author. Exemplars are good articles by other mature writers; the author's own drafts join only once the author approves them as representative of a settled style.

Before each article the organizer picks two approved rows whose type and length match, pastes both articles whole into the writer's brief with one line each on what to learn, and records the two in the editor notes. A missing type is a gap to fill, reported to the author.

| Type | Author | Title | Path or link | Length | How it opens | What to learn (title / opening / structure / language) | Author's note | Status |
|---|---|---|---|---|---|---|---|---|
| opinion | Example Writer | An example opinion piece | ~/writing/library/example-writer/opinion-1.md | 3200 | a feeling the reader shares, then a question | opening, how one point is pushed through | reads like a person talking | approved |
| case teardown | Example Writer | An example case teardown | ~/writing/library/example-writer/case-1.md | 4100 | the company's move, then the question it raises | structure | | candidate |

Types used so far: opinion; case teardown; hands-on review; method checklist; personal experience carrying a judgment. Add a type when an article needs one.
