# 品叔写作

## 来源与维护

- 原创身份：品叔原创（original）
- 原创归属与维护者：Aidan（品叔）
- 上游依赖：运行时无外部依赖；`scripts/audit_draft.py` 只需要 Python 3。
- 原创能力：判断成熟流程、四个作者批准点、九类文章结构、好文章是/否标准、跨供应商审稿链和模型路由。
- 分发状态：1.0.0 公开候选；不声明正式发布、tag、CI 通过或外部安装验证。

## 这个 Skill 做什么

它不是“模仿某个人腔调”的写作器，而是把粗糙想法变成值得发布的商业判断。AI 负责找材料、扩展思路、反驳自己、起草、审稿和查机械问题；作者决定选题、判断、标题大纲和最终是否发布。公开发布时遵守平台对 AI 辅助内容的披露规则，署名和原创归属属于作者。

默认输出简体中文。账号画像、禁用词、读者、长度、材料目录、草稿目录和审批人都来自显式配置：用户指定的配置文件，或当前写作目录下的 `pinshu-write.yaml`。配置格式见 `templates/config.example.yaml`。不要硬编码私人账号画像、个人 HOME 路径、具体厂商必用/必禁清单或未经核实的模型版本。

## 开始前先读配置

账号画像是权威：写什么、不写什么、读者是谁、长度和标题怎么验收，都以画像为准。Skill 与画像冲突时，跟画像走。没有配置时，如果用户已经说明账号和读者，可以继续，但在第一个批准点补齐画像、材料目录和草稿目录等问题，并在编辑说明里写明“未读取账号画像，只按通用底线检查”。只有账号本身未知时，才在开始前追问。

写任何中文正文前，先运行：

```bash
python3 scripts/audit_draft.py --rules
```

如果账号有禁用词表，加 `--banned-file <path>`。脚本输出中文规则，比模型记忆可靠。

## 四个作者批准点

只在这四处停下来等作者：

1. **选题**：作者从 3 到 5 张选题卡里选一个。
2. **判断**：作者确认成熟后的判断、它如何从初始想法变化、最强反对意见及回应。
3. **标题和大纲**：一页内给标题候选、完整小标题和文章骨架；作者一眼读不懂就失败。
4. **终稿**：审稿链完成后，交终稿和一页审稿表。

其他步骤连续推进。用户已经给出题目和角度时，视为批准点 1 已成立，从资料和判断成熟开始；用户只给一个情境或直觉时，先做选题卡；完全没有方向时，给一个有证据的读者议题短清单让作者选。即使用户说“你直接写”，也必须先确认判断再起草。

## 标准流程

| 步骤 | 动作 | 参考 |
|---|---|---|
| 0 规格 | 账号、读者、读者卡点、希望读完后改变什么、可能文章类型 | 本文件 |
| 1 选题卡 | 3 到 5 张卡；每张说明来源、读者现在为什么关心、常识底线 | `references/topic-and-judgment.md` |
| 2 资料包 | 每条材料有日期和来源；厂商说法、自述、二手材料要标身份 | `references/topic-and-judgment.md` |
| 3 判断成熟 | 种子判断、基准判断、扩展、反方、成熟判断 | `references/topic-and-judgment.md` |
| 4 标题大纲 | 选文章类型，写标题、小标题和一页大纲 | `references/plain-writing.md`, `references/article-types.md` |
| 5 起草 | 新会话起草，按可用模型能力选择写作者 | `references/plain-writing.md`, `references/model-routing.md` |
| 6 审稿 | 结构、事实、风险、语言分工审查；审稿只标问题不代替作者决定 | `references/review-chain.md`, `references/good-article-standard.md` |
| 7 归档 | 记录材料、修改前后和发布后反馈 | `references/review-chain.md` |

作者推翻某处时，退半步，不全盘重来：只改被批评的部分，保留没有被否定的判断和材料。

## 中文正文硬规则

违反以下规则，稿件不合格。规则 4、6 到 12 也适用于给作者看的选题卡、判断卡、大纲和审稿表，直接引文除外。

1. 一篇文章只证明一个判断；开头问题、证据和结尾回答必须指向同一件事。
2. 不编造作者经历、客户、对话、真实人物、公司、数字和约数。假设场景必须让读者看出是假设。
3. 不写没出处的“很多人说”“有朋友问我”“有人告诉我”。
4. 用普通话讲清楚。行业外读者不能卡住；外文名、公司、术语第一次出现要解释。
5. 来源列在正文后，不塞进句中括号。
6. 长短句正常混合，不连续碎句。
7. 不使用 em dash。
8. 少用单句反转句式，例如“不是 X，而是 Y”。
9. 遵守账号禁用词和 `scripts/audit_draft.py` 的默认禁词。
10. 不写元叙述，例如“本文想说”“接下来我们看”“总结一下”。
11. 全文只有一个 H1 标题；正文用全角中文标点；正文不加粗；不用 emoji。
12. 全文最多两个金句式收束；不用对仗口号和三连口号。
13. AI 相关事实必须当前；六个月以上的事实证据要更新或标年份，经典原则除外。
14. 不自报字数和模式计数；这些只认脚本结果。
15. 删除或移动段落后，全文搜索仍指向旧段落的句子。

## 四个标题点

读者先看标题、小标题、开头和结尾，再决定要不要读中间。

- **标题**：直接说明文章关于什么，最好就是判断或读者自己的问题。
- **小标题**：单独看也能懂，8 到 14 个汉字左右，顺序读下来能讲完整篇逻辑。
- **开头**：根据账号近期文章变换方式，可以用真实事件、数字、反常识句、问题或明确标注的假设场景。
- **结尾**：交给读者一个当下可用的动作、话术或检查表，回扣开头后停住。
- **作者一眼读不懂就失败**，模型冷读只作参考。

## 模型路由一句话

用当前工具里最强的中文长文模型起草；审稿模型尽量来自不同供应商。模型菜单会变化，本 Skill 只保存选择原则，不硬编码某个私人账号里的模型列表。细节见 `references/model-routing.md`。

## 机械检查

每轮审稿前、交作者前都运行：

```bash
python3 scripts/audit_draft.py draft.md --length 2500-4000
```

如果账号有禁用词表，加 `--banned-file`，文件一行一个词，UTF-8。脚本只计数和定位：有阻塞项时退出 1。通过脚本只是底线，不是质量证明。

脚本只定位问题，不能证明文章好。它会提示小标题长度、开头假设场景、外文术语、Prompt 冒号、段落突兀开头和账号禁用词。

## 交付格式

- Markdown。第一行是唯一 `# 标题`；正文用 `##` 小标题。
- 正文后放来源列表：每条写清支持什么、来源名和日期。
- 再写 `===EDITOR NOTES===`：待核事实、待确认作者经历、使用过的假设场景、刻意不用的材料及原因、文章类型、是否同供应商审稿、脚本检查摘要。
- 过程文件放在同一文章文件夹：选题卡、资料包、判断卡、大纲、审稿报告和草稿；目录来自显式配置，缺配置就询问。
