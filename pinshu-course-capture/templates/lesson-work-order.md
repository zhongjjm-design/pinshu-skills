## Four core results

1. An immutable source transcript.
2. A faithful edit.
3. A structured lecture.
4. Exactly one idempotent entry in the course map.

Generate active recall, learning practice, horizontal topics, and promotional materials only when enabled in the manifest.

## Authoritative inputs

- Core quality contract (must be read directly): `<absolute path>/references/core-quality-contract.md`
- Core contract hash: `<hash>`
- Assurance-mode production card: `<absolute path>/references/production-modes-and-budgets.md`
- Domain and content routing: `<absolute path>/references/domain-and-content-routing.md`
- Resolved domain adapters: `<list only adapters selected for this lesson>`
- Resolved content adapters: `<list only adapters selected for this lesson>`
- Source transcript: `<absolute path + sha256>`
- User-approved sample: `<absolute path + sha256; write "awaiting user approval" for the sample lesson itself>`
- QA contract: `<complete only for independent QA or targeted recheck>`
- Previous QA report: `<complete only for rework and targeted recheck>`

Ordinary batch lessons do not reload the complete Skill or unrelated references. Adapters may add terminology, source rules, risks, and content anchors; they may not weaken the core contract or add default outputs.

## Writable scope

- Temporary directory: `<absolute path>/lesson-<N>/`
- Faithful edit: `faithful.md`
- Structured lecture: `lecture.md`
- Uncertainty ledger: `uncertainties.json`
- Semantic self-check: `semantic_check.json` when independent QA is not selected
- QA report: `qa_report.json` when independent QA is selected
- Coverage map: `coverage.json`, required only for `strict`

Only the committer may write to the official course library or course map.

## Final review before submission

- Recheck people, accounts, brands, tools, numbers, dates, key cases, methods, constraints, and the opening, middle, and ending.
- Record only STT conflicts that affect proper nouns, numbers, facts, sources, or later verification.
- For `strict`, also perform block-by-block coverage.
- Formal external use goes through the shared external-use gate and is not part of internal acceptance.
