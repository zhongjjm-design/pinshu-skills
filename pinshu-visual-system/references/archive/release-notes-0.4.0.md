# 公开共享层 0.4.0：整篇配图返修与审看续跑

本版只抽取通用能力，不包含发布者的角色母版、账号映射、私有样张或反馈。公开核心继续保留来源锚定、最终平台图哈希审核、原生文字渲染回执及 PNG 元数据白名单门禁。

## 先看清整批，不靠文件名数图片

```sh
python3 scripts/contact_sheet.py --plan <过程目录/配图任务.json>
# 没有任务 JSON 时，只检查一个明确的图片批次：
python3 scripts/contact_sheet.py --folder <图片目录> --expect <预期张数>
```

生成本地看图墙，并列出缺图、目录外资产或大小写重复。墙页不是来源/身份/审美验收，打开每张原图与真实手机检查图后再作判断。

## 截图生成成功不等于内容合格

图片有遮挡、截断、错误对象或空白时，向同一截图输出目录登记实际拒绝原因：

```sh
python3 scripts/capture_evidence.py --url <来源网址> \
  --output-dir <该次截图目录> --reject "实际看到的具体缺陷"
```

拒绝同样计入失败次数；累计三次转人工指引。登记拒绝不启动浏览器，也不能凭空把未采集的图记作失败。人工截图须保留来源、时间和采集证据，不伪造自动工具的成功回执。

## 只换该换的一张

截图返修先由原截图工具得到新的成功采集目录，再更新同一个配图任务：

```sh
python3 scripts/replace_asset.py --plan <配图任务.json> --target <目标文件名> \
  --capture-dir <新截图成功目录> --by <实际处理人或Agent> \
  --reason "旧图的问题及这次改动"
```

生成式/自有可编辑配图使用 `--file <新图>`，并依类型提供 `--original-file`、`--publish-clean-report` 或 `--editable-source`、`--render-receipt`。所有产物留在本篇过程目录。工具只更新唯一目标，保留修订记录；截图仍必须是新无框图，旧带框标记不能沿用到新截图片上。不静默修其他工作区同名文件。

## 没变的图可有条件沿用上轮审看

```sh
python3 scripts/run_ready_article.py --article <正文.md> --kit <物料包.md> \
  --output-dir <新的过程目录> --space-id <已有ego空间号> \
  --carry-reviews-from <上一轮过程输出目录>
```

没有浏览器时只能加 `--prepare-only` 做准备包，不宣称完成手机实看。已知需求先更新同一任务，并按 `--bind-kit` 绑定当前物料包再跑。

沿用只适用于成图字节、模板、槽宽、位置/正文上下文和最终可见图注均未变化的图；不因为 HTML 的无关部分改变就全量重审，但真正改变的上下文不能沿用。没有足够绑定字段的旧回执须重审。当前轮已拒绝的结论不被旧通过记录覆盖。沿用结果由工具明确列出，缺失或失效项仍待实际审看。

## 七款排版与新块

排版支持七款模板（含 `--template split`）、2–4 列表格与提示词卡。双栏标题选择由任务的 `heading_split` 显式透传到排版。表格或提示词卡既要通过排版解析，也要通过整篇预览的可见文字一致性校验；准备模式成功不能替代正式手机流程。

为兼容旧目录引用，工作页子目录仍叫 `六款试排`；实际输出七款，不额外生成仿制章节图片。

## 仍需使用者验收

- 先用“主体—动作—对象”锁定封面图意，低成本单样成立后再扩风格；正文图按手机图槽控制复杂度。
- 任意程序 PASS 都不证明图意正确、身份授权成立或审美被接受。
- 微信后台粘贴与真机效果、付费生图、真实登录截图和特定角色组合仍须当前任务单独验证。
- 本地计划、QA、来源快照、手机检查图和过程回执不随成图公开分享；分享最终 PNG 继续使用 `export_share.py` 的白名单边界。
