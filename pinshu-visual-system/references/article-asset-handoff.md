# 写稿、配图、排版的交接

2026-10-10 私人候选接口。本文是三段交接的唯一说明；七字段视觉卡、角色与风格库保持各自职责。

## 谁负责什么

| 环节 | 交付 | 交给下一环节前判断 |
|---|---|---|
| `pinshu-write` | 明确版本的正文及来源；配图需求；收尾时已截的证据截图（2026-10-12 起写稿也截） | 哪个论点需要图、为什么、放在哪段、有哪些真实出处；写稿截的图同样只用 `capture_evidence.py`、同样过“打开看图”验收，视觉读物料包核对，不全或不合格的补截 |
| `pinshu-visual-system` | 选素材、生成/截图/处理实拍、成图与两份 JSON | 图意、来源、手机可读性、首图嵌入和整篇效果 |
| `pinshu-wechat-layout` | 本地整篇预览、可复制正文和独立发布字段 | 原文保持、图片位置、图注与来源、版式及实际微信效果 |

配图不是写稿或排版里的临时生图动作。写稿可以建议素材类型与出处，视觉环节可以发现更好的选择；换掉支撑论点的证据需回到写稿核对。排版发现图不合适，带具体上下文退回视觉环节，不静默抽图。视觉探索可在别的对话进行，接入时交文件路径、出处和用户反馈，不能靠另一个对话“记得”。

正常接活先读取用户指定的待发布正文和配对发布物料包，按 主文件安排的 ready-folder-contract.md 核 YAML 文件信息、过程目录和配图任务路径，不自动挑最新稿。物料包截图清单决定出处、准确区域、放置段落和作用；Agent 保持同一任务 JSON 与其一致。下文的素材、截图与审看细则继续完整执行。

尚未定稿的显式试验才使用指定草稿版本及写稿 `export_article.py` 分离编辑备注，不伪称已定稿。写稿导出保留 YAML 文件信息，视觉流水线进一步分离文件头，供排版与复制正文使用；原文与来源字节保留。记录原稿和派生正文 SHA256；正文或来源更新后重核受影响锚点，不自动全套重做。完成/部分完成/失败回写物料包“配图排版进度”，附可点击预览路径。

## 同一配图任务，四种生产来源

`asset_kind` 是素材来源与生产方式，不是新的 `mode`、人物或品牌风格；一篇可混用。注册表的 `article-illustration-package` 仍是整篇任务，生成式分支沿用现有编译器；来源素材不伪装成编译器输出，不增加截图风格 ID。

| `asset_kind` | 适合的作用 | 制作与来源记录 |
|---|---|---|
| `generated-visual` | 解释关系、假设场景、视觉叙事 | 原生生图、已有角色/风格路由与净化流程；不能冒充实拍或原帖 |
| `evidence-screenshot` | 展示文中引用的原话、操作或页面 | 原帖/官方页面原始截图、链接、作者、实际截图时间；浏览器精确取景 |
| `real-photo` | 展示真实人物、产品、现场、实物 | 用户提供或可用来源的原图、摄影者/提供者与来源说明；必要的裁切、缩放、处理另记 |
| `rendered-graphic` | 精确解释数字、步骤和关系 | 自有可编辑代码/SVG/HTML 等源、实际渲染器、绑定源与成图哈希的回执；`image_model: null`，不记为 AI 生图 |

`image_function` 为 evidence / explanation / concept，是理解作用，不能当素材来源。新任务在已有资产项中记 `message`、`visual_relation`、`feedback_ids`、`feedback_response`；AI 项另记 `generation_reason`。写稿提供判断与原文位置，视觉重读前后文核实，不机械照单制作。工具保留这些元数据，旧清单仍兼容；字段存在不证明图意成立。

来源资产完整保留，只在副本上处理。截图证明来源当时显示了什么，不直接证明其中的主张正确；浏览量等动态数字写清截图时间。实拍不得用 AI 重画或修改事实后继续称原始实拍。截图和实拍不套自有 IP 身份规则，也不批量清掉来源凭证。图少而有效，不为凑数加入三种素材。封面仍需单独建立阅读承诺，不默认把正文截图拉伸为封面或叠一遍文章标题。

### 无框高清截图

浏览器操作先读 `ego-browser`，用其现有 TaskSpace/Page API。帖子按所引用的帖子卡片裁；长文按准确文字起止区间定位，例如 DOM Range。检查原话、上下文和出处身份，不能只截到一句断章。

截图异常先按实际现象定位，不能将经验当作跨网站保证：目标文稿目录写失败时先写当前运行时批准的临时目录，核图后再搬；先核对裁剪 API 使用视口还是整页坐标，只有坐标系转换需要才加滚动量；吸顶栏遮字时临时隐藏遮挡并记录、恢复页面，不能改变证据正文；长文本元素包含多段时使用文字区间定位，不能直接截整个元素。

品叔已定：截图像素中不加框、不烘焙背景/圆角/阴影，交接 `frame_baked` 默认为 `false`。统一边框由 `pinshu-wechat-layout` 模板加。`frame_screenshot.py` 仅保留为旧任务回查工具，不用于制作新截图，也不为现有旧图自动拆框重做。旧成图已烘焙边框时如实保留 `true` 防止叠框；新截图按无框规则制作。

约 600px 宽的 1 倍截图不能放大到 1080 冒充高清。按准确区域调用已有 ego-browser Page 的 CDP 接口（不另起浏览器），在 `clip` 中设置 `scale: 2`，保存原始高分辨率 PNG，再等比缩到 1080px。例如 CSS 区域宽 600，目标是约 1200px 原图；实际像素受运行时设备比例影响，必须打开文件核尺寸，而不是只看参数。原始截图窄于交付宽度时，先区分 DOM 文字和内嵌栅格：文字可提高捕获 scale；栅格图片/视频必须核原生像素，不能靠更高 scale 补细节。高清仍要检查手机文字大小；长文可按准确文字区间拆图。

下面示例只说明已定位区域如何捕获；`region` 来自已核对的帖子卡片或 DOM Range，示例选择器需换成实际页面对应元素。布局稳定、字体/图片加载后定位。`getBoundingClientRect()` 是视口坐标；这里加当前滚动量转换为整页 CSS 坐标，只加一次，不混用已是整页的坐标。

```js
// 在已建立的同一个 ego-browser TaskSpace 内，page 为已打开的来源页。
const fs = await import("node:fs/promises");
const region = await page.evaluate(() => {
  const r = document.querySelector("#exact-quoted-region").getBoundingClientRect();
  return {x: r.left + scrollX, y: r.top + scrollY, width: r.width, height: r.height};
});
const result = await page.cdp("Page.captureScreenshot", {
  format: "png", fromSurface: true, captureBeyondViewport: true,
  clip: {...region, scale: 2}
});
await fs.writeFile("/tmp/03-原帖原话-2x.png", Buffer.from(result.data, "base64"));
```

用 Pillow `LANCZOS` 等比缩小副本到 1080，保留高分辨率原图，记录裁剪区域、scale、原图与交付图的实际尺寸及哈希。输出目录写入受限时，按上方已知退路先写 `/tmp`、核图后再搬。禁止 AI 重绘、锐化造字或修改原话来弥补低清。底层接口参考：[CDP Page.captureScreenshot](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-captureScreenshot)。本团队的 X 页面实测是已有案例，不据此保证所有页面都可相同取景。

### 手机取景与本轮采集记录（实跑修订）

图是否展示了原文需要的证据，先于高清和可读性。展示成片效果的任务须含实际视频画面及出处身份，不能为了通过媒体/分辨率门禁退成只有原话。预期媒体按任务需要声明，不能先删掉核心对象，再把预期数量降为零。实际暂停帧与官方海报分别记录，不能无说明互换。

高清和可读是两项检查。正文里的长文字截图，优先将真实网页重排到 390px 左右的窄屏，再按完整引用段落取景。不要把 1200px 的桌面文字页面直接缩进约 290px 的正文图槽。精确截取有上下文的完整原话；不能删字、重绘或任意放大局部后冒充完整原帖。无法窄屏重排的原帖内嵌表格，先保留来源上下文，再取关键行的真实细节；当前每段一图，不支持的组合需回到原文位置重新判断，不静默换证据。

每张取景先核对应段落与来源的对象、指标和条件。官方文章讲多个产品时，只截正文实际谈到的小节，不让相邻套餐说明造成歧义；原帖图片先看前后原话再选来源资产。截图要展示结果时保留结果；要证明原话时保留完整原话。原图与每次真实手机图都由Agent主动看，不等待用户指出：关键片名、数值、列名/单位和末行应在正文图槽直接读清。高清原图或点击放大不能补正文读不清；先窄屏重截、收紧无关区域/列，再考虑下方有披露的局部拼接，仍不清就标返修。

### 截图规矩（2026-10-12 修订，先看这一段）

1. **只用 `scripts/capture_evidence.py`。** 不许临时写截图脚本：临时脚本没有空白、遮挡检查，10-10 的白图就是这么来的。工具做不到的，走第 7 条转人工。
2. **帖子里有视频或图片，画面必须一起截进去。** 作者、原话、画面、浏览量放在同一张图里。不许为了过清晰度检查，把视频裁掉、只截一两句话。
3. **按用途选 `--purpose`。** `quote`：证明原话和数字，视频分辨率低只记进回执，不拒收。`visual`（默认）：展示画面本身，画面不够清楚就拒收。
4. **外文来源默认截中文版。** 加 `--translate-to zh-CN`，工具走谷歌翻译中转页；图注写“原文为外文，截图为机器翻译”，外文原图另截一张留底。这时 `--start`/`--end` 要填**中文译文**里的字（先打开中转页看译文再填），填外文原文会匹配不上。网站挡中转（如 note.com）算一次失败。X 帖子先点“翻译帖子”再截。
5. **X 主帖这样定位：** `--selector 'article[data-testid="tweet"]:has(a[href$="/status/<帖子编号>/analytics"])'`。X 现在所有帖子都是 `tabindex=0`，旧写法 `article[tabindex="-1"]` 已失效。
6. **工具自动做的事：** 每次都重新打开页面并回到顶部；藏掉浮动栏、吸顶栏和浏览器插件的悬浮按钮（如 Monica、YouMind）；把 ego 的光标挪出截取区域；四周留 10px 边。藏了哪些写进回执的 `auto_hidden_overlays`。选择器不好写时，用 `--clip X Y 宽 高` 按坐标截。
7. **同一网址自动失败 3 次就停。** 工具自动生成 `人工截图指引_<名字>.md`（打开哪个网址、截哪一块、怎么截、存到哪、文件名），第 4 次直接拒绝。加 `--describe "<大白话描述要截哪一块>"`，指引才写得明白。其余配图和排版照常往下做。用户要求继续试时才加 `--allow-more-attempts`。
8. **截完必须打开看图。** 看有没有遮挡、截断、空白，原话全不全。工具报成功只是最低要求。有问题当场重截。
9. **修好的图放回原位。** 放回文章过程文件夹的 `配图/`，再在物料包“配图排版进度”里留一行：谁、什么时候、改了什么。只留在自己工作区，不算修完。

观察来源页后，复用同一 ego TaskSpace 调用：

```sh
python3 scripts/capture_evidence.py --space-id <当前spaceId> --page p1 \
  --url <原帖URL> --selector <已观察到且唯一的CSS选择器> \
  --start <准确起始原话> --end <准确结束原话> --purpose quote \
  --describe "<大白话：截哪一块>" --output-dir <新截图目录>
```

不传文字区间时截完整元素。工具用移动视口、DOM Range 和 `Page.captureScreenshot`，按区域自适应至少 2 倍捕获；实际原图低于 1080px 或近空白会失败。区域内图片（含透明 img 代理及 CSS 背景）须加载完成；视频须有已加载的帧或可用海报，可见 progressbar/aria-busy 未消失则失败。默认等待最多15秒，`--media-timeout-ms` 可设100–30000毫秒；失败留下 `采集失败.json`，不能生成成功回执。等待完成仍须实际打开看图，不保证任意网站的自定义转圈均能识别。若计划取景区域本来有视频，Agent须按观察结果声明 `--expect-media video:1`；有多个视频填写实际下限。同一区域原本有主体图片时可声明 `--expect-media image:N`（已加载的不同主体图片URL数，不含小头像/图标；透明代理与同URL背景只计一份）。声明可重复传不同种类。工具等待该区域达到预期数量，缺少时记 `EXPECTED_MEDIA_MISSING`，即使视频已被网站替换成报错面板也不交成功图。声明针对所截区域，不是整帖：只截身份与原话且不含媒体时，不声明区域外的视频。未声明不能证明网站未把媒体换成自定义错误面板。

截图文件宽度不代表来源清晰度。工具记录区域内主要栅格的原生宽度，以及该栅格在最终1080副本中的预计像素宽度；原生像素不足时，`--purpose visual` 拒用，`--purpose quote` 只记录不拒收（小头像/图标不作主体清晰度门禁）。该比较用交付尺寸，不用2倍超采样原图尺寸。网页里的680px图片即使拍成1420px，也不能通过。视频只有640px帧时，不能当近1080px的高清主体展示；但要证明原话和数字时，用 quote 照样把画面截进去。文本区间终点取结束原话所在节点的末尾，不能落到下一段开头而把中间媒体带入选区；01可截身份与原话，不因边界错误降低栅格清晰度要求。先写临时目录，再保留原始 PNG 和等比缩小的无框副本；记录实际尺寸、区域、原话、时间和哈希。浮动和吸顶元素工具会自动藏，`--hide` 只在自动没藏到时补传已观察到的唯一选择器，不能隐藏证据或其祖先，截完恢复。截取失败先检查页面再试；同一网址失败满 3 次按上面第 7 条转人工。没有浏览器则走下面的待截图交接。

内嵌数据表/图片优先取页面实际引用的来源原图，再按原生像素裁切。先观察真实 `currentSrc`，只允许同域同路径资产的原图参数，不能猜其他素材替代：

```sh
python3 scripts/capture_evidence.py --space-id <当前spaceId> --page p1 \
  --url <原帖URL> --selector <已观察到且唯一的IMG选择器> \
  --native-image --image-source-url <同一资产的原图URL> \
  --native-crop <X> <Y> <WIDTH> <HEIGHT> --output-dir <新来源原图目录>
```

`--image-source-url` 和 `--native-crop` 均可省略；原图直接通过现有 Page.fetch 保存，原始文件保留，PNG副本只裁切/缩小。原图不足1080按实际像素交付，不插值、不伪称1080高清；手机读不清仍须细节取景或退回素材判断。裁切必须保留可核对的行列/单位及上下文；它是来源图片提取，回执 `capture_method: native-source-image`，不是整页截图，也不自动把引用身份、上下文或手机审美标通过。

### 宽表的局部拼接：原图裁切、自动披露

仅当连续裁切仍不能在正文图槽读清，且局部组合能保留同一证据关系时使用。优先同一来源原图；每条保留识别信息（如原封面/片名）和所讨论指标的原列名/单位/数值，保持原顺序与一一对应。不能抽掉限定语、换指标、混合不同来源/时点、拼成原网页没有的连续现场，也不重画文字或放大原栅格。需要换顺序或跨来源对比时另做明确署名的解释图，不走本工具。

Agent在当前配图任务中选唯一PNG文件名，写取景配方后运行固定工具，不再为每篇写Python临时脚本。配方的 `delivery_size` 是无框画布原像素；`regions_native_pixels` 含每块的 `role`、原图 `[左,上,右,下]` 的 `source_box` 和画布 `[左,上]` 的 `paste_xy`。`caption` 写来源和选取内容，必须明确“局部拼接”，如“截图来源：Tom CC｜原后台封面与评论列节选（局部拼接，顺序未变）”。坐标由当前原图实看确定，不能照搬05。

```sh
python3 scripts/compose_evidence.py --plan <当前配图任务.json> \
  --filename <该项唯一文件名.png> --recipe <本图取景配方.json> \
  --output-dir <新的局部拼接目录>
```

工具核原稿、原图/出处/采集时间绑定，只裁切平移，拒绝越界与互相遮盖；输出PNG、配方与新回执，保存输入任务备份并自动回填同一任务项的成图、图注与待审状态。`captured_at` 沿用来源采集时间，`processed_at` 另记处理时间，旧原图不会变成今日新截。新回执绑定原图/成图指纹及全部坐标；交接再次按原图重建核像素，不只相信“像素一致”声明。

排版交接对标为montage的截图自动保留非空“局部拼接”图注，漏写或显式空图注也不能隐去该披露；出处链接仍只留机器交接/原稿来源。`frame_baked=false`，边框由模板统一加。拼接工具不判断所配行是否正确、遗漏条件是否误导或手机是否可读，仍须看原图与整篇；一次05成功不代表所有宽表都适用。

截图项记录 `acquisition: new-capture | reused | unknown`，含义是该次文章采集是否新截；旧图不能因为今日重新缩放而改成新截。复用项保留原来的时间，不编造精确时间。`capture_receipt` 保存采集回执；`mobile_review` 保存 `state` 与具体问题、看图文件/哈希和检查者。回执与旧审看必须核对成图哈希，不因复制元数据自动认定当前文件已验收。旧清单兼容，但审看缺 `image_sha256` 时旧结论降为 unknown；有指纹但不匹配直接失败。`new-capture` 必须有回执中的交付哈希和实际时间，且时间、出处、保留原图哈希与资产一致；无绑定回执降为 unknown，不能因为旧记录写了新截就确认采集。复用不冒称现场新截。

整篇工具自动保存 320/375/414px 布局检查和 375px、deviceScaleFactor=3 的首屏与逐图截图；超过一屏的图按900 CSS像素步长分段，每屏1000 CSS像素，保留重叠及末行。Agent 必须打开这些图片审看：关键原话是否可直接读、末行/左右是否完整、图像是否空白或压扁。可用 `源字体CSS像素 × 正文图槽CSS宽 / 截取区域CSS宽` 估算文字在手机上的大小；低于 12px 是重新取景的提示，不是所有语言/字体的统一验收线。该估算不覆盖来源页里的内嵌图片，须实际看图。放大入口用于核细节，不使一张正文读不清的图自动通过；仍有问题记 `needs-reframe`，不将技术 PASS 写成手机可读性通过。

### 没有截图工具时继续交接（退路）

当前 Agent 没有浏览器、不能登录来源页或缺截图能力时，不停在“无法截图”，也不改用 AI 生图。重读原文引用与上下段，在同一 `配图任务.json` 的截图项填：`source_url`、`capture_region`（准确文字起止、帖子卡片或页面区域）、`after_paragraph`（放在这段完整原文后）、排版用唯一 `after_prefix`、约定的 `filename`、`purpose`。`review_state` 写 `capture-pending`；未截就不填写实际 `captured_at`、原图文件或完成状态。

复用交接工具只导出待截图清单，不依赖浏览器、Pillow 或排版 Skill：

```sh
python3 scripts/prepare_article_handoff.py --plan <配图任务.json> \
  --output-dir <新截图交接目录> --capture-requests-only
```

输出 `待截图清单.md`（给人）与 `待截图清单.json`（给 Agent），包含正文路径/哈希、出处、准确区域、放置段落/锚点、约定文件名、无框要求及高清要求。它们是待采集交接，不冒充排版可发布清单。将清单交给具备截图能力的 Agent，或人工用授权截图工具手动截；未经用户授权不自动向其他会话发消息。其余读稿、构思和已具备素材的准备继续做。截图回填后再核原话、尺寸、来源和原文哈希，生成正式排版两 JSON，不能把缺证据项静默删掉来称整篇完成。

## Agent 维护一份任务，不让用户填 JSON

在当前文章生产记录中维护 `配图任务.json`。写稿阶段确定 `source_md`、`article_sha256` 和每项 `role`、`purpose`、`after_prefix`、拟选 `asset_kind`；引用截图附 `source_url`。没有真实需要的图可不列。视觉阶段在同一项填最终 `file`、来源、处理与检查状态，不另建一份重复需求单。

完成后的机器输入示例（路径可绝对或相对本 JSON；以下值都是格式示例）：

```json
{
  "source_md": "/文章/正文.md",
  "article_sha256": "正文文件真实SHA256",
  "author": "品叔",
  "digest": "",
  "article_state": "候选待作者确认",
  "assets": [{
    "role": "body",
    "purpose": "让读者直接看到文中引用的提示词",
    "after_prefix": "此处填写唯一段落的准确开头",
    "asset_kind": "evidence-screenshot",
    "file": "成图/03-原帖原话.png",
    "original_file": "原始截图/03-原帖原话-2x.png",
    "source_url": "https://example.com/original-post",
    "attribution": "原帖作者",
    "captured_at": "实际截图时间",
    "processing": ["精确取景", "2倍捕获", "等比缩小至1080px"],
    "frame_baked": false,
    "alt": "供屏幕阅读器使用的图像描述",
    "caption": "明确交付给读者的图注",
    "review_state": "Agent 已看；用户待确认"
  }]
}
```

`role` 为 `body | cover_landscape | cover_square`，封面对分别列两项，不拉伸复用。正文 `after_prefix` 必须对应排版解析后的唯一段落开头，不是段落结尾或任意包含的短语。当前排版每段最多一图，H2 不限六章；经典版 01–06 用既有图片、07 起用文字章号。2–4 列表格和提示词卡可用；内嵌图片、原始 HTML 和代码块仍不支持；发现不适配就说明具体缺口，不静默删正文。无图时 `assets: []`。

生图项提供 `publish_clean_report`，工具核对 PASS、AE=0 和发布副本哈希；归档图改了文件名也可按像素文件哈希匹配既有净化副本。截图项提供 `original_file`、`source_url`、`attribution`、`captured_at`；实拍项提供 `original_file`、`attribution`，可加 `source_description`、`source_url`。来源信息由实际采集/提供记录填入，工具不能替你证明作者、授权或内容事实。图意 `purpose` 必须由 Agent 在清单里写明，不能由文件名推断。

确定性图形项提供 `editable_source`、`renderer`、`render_receipt` 和 `attribution`。渲染完成时生成回执：`source_sha256` 为可编辑源真实哈希，`output_sha256` 为交付 PNG/JPEG/WebP 真实哈希，`renderer` 与资产项一致，`image_model: null`。交接核对绑定，不要求生成器净化报告；回执不能证明图中数字/关系正确，仍需对原文逐项核对。依赖额外数据/字体/模块的源要在生产记录列清，不把一个源哈希宣称为整个环境可复现。

## 生成排版可直接消费的交接

```sh
python3 scripts/prepare_article_handoff.py --plan <配图任务.json> --output-dir <新交接目录>
python3 <pinshu-wechat-layout>/scripts/build.py --handoff <新交接目录/排版交接.json> --output-dir <新试排目录>
```

依赖 Python 3、Pillow、已安装的 `pinshu-wechat-layout` 及其 `markdown-it-py`、`beautifulsoup4`。工具直接复用排版实际解析器，不另维护一套段落规则；非相邻安装可传 `--layout-skill`。不安装缺失依赖，不覆盖输出，不改输入，不发文。

输出沿用排版已有 `配图清单.json`（原稿路径/hash、每个成图文件/hash，素材来源、采集与手机审看记录）与 `排版交接.json`（作者/摘要、封面名、正文文件名及段落锚点）；成图副本与清单放同目录，保持原始来源资产原位。新截图默认 `frame_baked: false`，使用模板统一框；兼容旧已加框资产的 `true`，逐图防止二次衬框。`caption` 与 `alt` 分开：图注只显示纯文字，不生成“原始出处”外链，不重复署名。未提供 caption 时有来源署名就显示文字署名，否则回退 alt；显式空 caption 则不显示图注。`source_url` 保留在机器交接/来源记录，不能为了去外链手工删掉。原稿自身资料来源及链接不改。

### 同一入口串联导出、交接与轻量试排

Agent 维护同一配图任务，素材就绪后在现有 ego TaskSpace 内运行，不让用户手工抄写 JSON 或拼预览 HTML：

```sh
python3 scripts/run_article_pipeline.py --draft <明确选定版本.md> \
  --plan <配图任务.json> --output-dir <新整篇试排目录> --space-id <当前spaceId>
```

入口复用写稿导出、视觉交接和七款真实排版渲染器；默认青灰手记，可指定 `--template`。核对选定稿/导出正文与任务原文哈希，不自动选最新稿或重写失效锚点。自动导出正文（不含编辑备注）、正式两 JSON、七款工作页、保留模板内联样式的轻量整篇 HTML、逐图手机检查图、来源/采集记录和各阶段工具耗时。图片来源网址仍留在清单；预览图片可点击打开本地高清文件，图注无外链。总工具耗时不冒充整项构思、采集、返工与等待耗时。

`流程核验.json` 中技术检查、Agent 看图和用户验收分开；每项未知/未审的手机记录会继续标待看，不算通过。工具不自动替换证据、不改正文、不上传/发布、不代替用户决定。Agent 看完逐图的全部手机分段后，用独立审看工具记录；重要截图字小须重新取景，不能仅改状态。一次本地复跑不能证明微信真机效果或长期成功率。

`流程核验.json` 是流水线原始输出，不手改审看字段。总状态 `TECHNICAL_CHECKS_PASS_VISUAL_REVIEW_PENDING` 只表示技术检查完成，`ready_for_user_review: false` 表示素材仍待当前上下文审看。失败时记录 `FAILED`、失败阶段和已有部分输出，不能把部分产物交作完成；图少或无图以任务实际需要为准。

```sh
python3 scripts/record_article_review.py --run-dir <整篇试排目录> \
  --filename <交接中的图名.png> --state readable \
  --note <已实际看到的具体结论> --reviewer Codex \
  --meaning-note <对应哪句正文；画面是否保留同一对象、指标与条件> \
  --legibility-note <手机图槽能直接读到哪些关键内容；末行是否完整> \
  --view <手机检查/01.png> --view <手机检查/01-part2.png>
```

新流水线将排版实际匹配的段落、图的作用和出处带入每张截图的 `evidence_context`，并要求审看同时记录图意和手机可读性。局部拼接再传 `--composition-note <核对原图对应关系、顺序和图注披露的实际结论>`。缺任一所需观察，不能登记为readable；图意不对用context-check-needed，关键字读不清用needs-reframe。旧流水线没有这些要求，保留为历史记录，不作新版流程的图意检查证据；重跑后实际看当前图，再登记。文字字段齐全也不能替代实际判断，不把工具拒缺项写成自动理解图文含义。

`--view` 须覆盖该图实际生成的全部分段，短图只传一项。流水线在原始回执的 `screen_sha256` 中记录每张手机检查图的指纹；登记前核对文件集合及内容哈希，手机图被替换/缺失时当场拒绝，审看后替换也使派生状态阻塞。旧流水线回执没有手机图指纹时需重跑，不手补原始JSON来绕过检查。状态为 readable / needs-reframe / context-check-needed；工具追加 `审看记录.jsonl`，绑定成图指纹、模板、图槽CSS宽度、整篇HTML指纹及所看文件指纹，再更新派生的 `交付状态.json`。换图、模板、宽度、最终可见图注或正文/图槽上下文后，该图旧结论不沿用；重新运行并实际查看。仅无关 HTML 改动时，可用带绑定校验的 --carry-reviews-from 沿用未变图片，不能手补回执。派生状态在所有阻塞消除后可为 `READY_FOR_USER_REVIEW`，仍不代表用户已接受或已在微信真机验收。

待截图退路核对 `after_paragraph` 为原文完整段落（保留原Markdown），短语命中不能替代整段。依赖不同机器时先核解释器与包，不自动安装；本机2026-10-10核验：`/opt/homebrew/bin/python3.14 -B` 可跑本流程，`/opt/homebrew/bin/python3.12 -I` 有PyYAML、可跑三个Skill的quick_validate。这是本机环境记录，不是跨机器保证。ego CLI可用 `PINSHU_EGO_BROWSER` 指定，或由PATH查找；无工具仍按退路输出清单。截图/手机检查结束或异常都清理临时设备模拟，在同一TaskSpace恢复，不另建会话绕错。

无浏览器时用 `--prepare-only` 明确只到本地七款试排，实际打开/滚动检查仍待完成；任务中有未完成截图时，入口自动输出待截图清单并标 `CAPTURE_PENDING`，不静默删掉缺图项。仍需填准确区域/完整放置段落，缺失时报具体字段而不是编造。首图嵌入、用户图意/风格/阅读验收继续遵循 主文件已安排的 workflow.md。文件校验不等于验收。

工作台以后调用这三个环节、引用同一原稿及交接路径/hash即可，不再复制配图规则。当前只验证本地工具间接口；未实现工作台接线、微信上传或自动发布，排版完成不代表发布授权。

## 采集状态与旧框回执

进入已完成素材交接的证据截图必须显式写 acquisition：new-capture、reused 或 unknown。新截及未知截图不能 frame_baked:true。旧带框图仍可复用，但必须明确 reused，capture_receipt 含旧 captured_at 及与当前成图一致的 delivery_sha256 或 output_sha256；缺失或错配即拒绝。待截图清单尚无成图时不要求编造采集状态或回执。模板呈现衬框照旧；这项不修改截图像素。
