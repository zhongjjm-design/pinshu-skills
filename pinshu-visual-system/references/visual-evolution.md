# Visual formats and continued evolution

Maintain this as a visual system for article illustrations and covers, Xiaohongshu carousels, WeChat image posts, seasonal/event posters and promotional posters. These are intended uses, not a claim that every format or style has passed acceptance. Choose the audience, purpose, source message and destination before choosing a visual style. A poster may need atmosphere and one strong anchor; a knowledge carousel needs progression across pages rather than repeated cover layouts.

The platform registry contains project presets, not guarantees about current platform rules. For WeChat image posts, confirm the intended publishing surface with the user: wechat-sticker is an internal sharing preset, not a universal Xiaolvshu specification. For a poster without a matching tested preset, agree the actual canvas and delivery surface and record that gap; do not silently treat the generic square preset as a validated poster export route.

## Learn from references and use

When the user supplies a useful image, record its source, any reuse restrictions, intended format and specifically what the user likes. Extract transferable composition, typography, color, material, narrative and information hierarchy. Separate a reusable method from the original artwork, character or brand identity; keep private references local and distribute only material cleared for sharing.

Compare the proposed method with existing cards. Amend a card when the increment fits; add a candidate when it introduces a distinct useful approach. Avoid making a new Skill for every style. A reference the user likes is evidence about taste, not proof that our implementation works.

Test the method on a real new subject and intended platform. Show the full image and actual reading-size preview, obtain the user's design judgment, and keep engineering checks separate. Before using it for a series, vary the subject, composition and reading direction and check whether the results remain coherent. Preserve rejected attempts and their feedback as learning evidence, not as approved templates. Promote methods only within the formats actually tested and accepted.

For colleague feedback, retain the input, intended platform, selected card, Skill version, actual model/tool when reported, final image and concrete failure or improvement request. Reproduce the issue, make the narrow supported change and rerun the relevant checks. Sharing a preview does not establish unattended batch maturity.
